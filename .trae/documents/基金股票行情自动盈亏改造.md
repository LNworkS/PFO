# 基金/股票行情自动盈亏改造方案

## Context（为什么做）

用户要求：
1. 资产类账户类型「账户」（id=`account`）改名为「基金」。
2. 「基金」「股票」两类应像「货币理财」（`rateKind:'fund'`）一样，自动匹配标的行情、逐日计算当日盈亏。

现状：`account` / `stock` 都是 `rateKind:'manual'`，只按手填年化利率计息，不拉行情、不算涨跌。货币理财已有一套成熟的行情链路（`RateFeed` + `preloadForAccounts` + `refreshInterest` 逐日复利），本次把这条链路扩展到基金净值与股票价格。

目标：基金按**单位净值日环比**、股票按**前复权收盘价日环比**，逐日复算账户市值并生成盈亏流水，账户卡片显示「今日涨跌 / 日盈亏约」。

## 数据源可行性（已实测，本机 curl 验证）

| 用途 | 主力 | 备选 | 备注 |
|---|---|---|---|
| 基金净值 | 天天基金 `api.fund.eastmoney.com/f10/lsjz?fundCode=..&pageSize=200` | 东财 `fund.eastmoney.com/pingzhongdata/{code}.js` 读 `Data_netWorthTrend` | lsjz 需 Referer `https://fundf10.eastmoney.com/`，返回 `DWJZ`(单位净值)/`JZZZL`(当日涨跌%)；pingzhongdata 的 `Data_netWorthTrend` 为 `[{x:ts,y:净值,equityReturn:涨跌%}]` |
| 股票行情 | 东财 `push2his.eastmoney.com/api/qt/stock/kline/get?secid={m}.{code}&klt=101&fqt=1&lmt=320` | 腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={prefix}{code},day,,,320,qfq` | 东财返回 `klines:["日期,收盘",...]`；腾讯返回 `qfqday` 数组（第 2 项为收盘价） |
| 股票名称匹配 | 东财 `searchapi.eastmoney.com/api/suggest/get?input=..&type=14&count=8` | 手动填代码 | 返回 `Code`/`Name`/`QuoteID`(形如 `1.600519`，即 secid) |
| 基金名称匹配 | 复用现有 `searchFundByKeyword`（`fundsuggest.eastmoney.com`） | 手动填代码 | 已验证可用 |
| 蛋卷 `danjuanapp.com` | — | — | 本机返回 403，不作为新链路数据源（现有 rate 链路保持不动） |

## 设计决策

- **D1 命名**：`ACCOUNT_TYPES` 中 `{id:'account'}` 的 `name` 改为「基金」，emoji 改为 `💹`。**保留 id `'account'`**，历史数据无需改 id。
- **D2 計息种类**：`account` → `rateKind:'fund_nav'`；`stock` → `rateKind:'stock'`。
- **D3 盈亏模型**：账户 `balance` = 当前持仓市值。逐日复算 `市值_t = 市值_{t-1} × (1 + 涨跌幅_t)`，当日盈亏 `= 市值_{t-1} × 涨跌幅_t`。非交易日（周末/停牌/无记录）涨跌幅视为 0。
- **D4 复用**：新建 `QuoteFeed` 模块，**直接复用** `RateFeed.loadScript(src,url)` / `RateFeed.loadHttp(src,url)`（两者只依赖 `src.parseScript/parseJson/headers`）。`QuoteFeed` 自带 `_cache`（key `${kind}:${code}`）、自带 `SOURCES`，按「主力→备选」静默重试，**不写配置、不弹数据源设置弹窗**，仅内存缓存不落盘。
- **D5 不动 RateFeed**：`RateFeed.CATALOG` / `getConfig` / 数据源设置弹窗（`renderRateSourceModal`）完全不动，避免破坏刚验证过的余额宝链路。
- **D6 兼容历史数据（关键）**：`fund_nav` / `stock` 采用**双模**——已绑定代码且行情可用 → 按涨跌计盈亏；未绑定代码 → 若 `interestRate>0` 仍按年化计息，否则不计息。这样旧的 `type:'account'`/`'stock'` 账户（已填手动利率）计息不中断，用户可自行选择绑定标的或继续手动利率。
- **D7 交易记账**：每日盈亏生成一条流水；盈亏为正 → `income`/`invest`，为负 → `expense`/`other_exp`；note 形如 `基金净值波动 · {账户名}（{来源}，{N}天）` / `股票价格波动 · ...`。
- **D8 每月 1 日提醒文案**：因基金/股票已自动跟踪，改为提示更新「保险（手动利率）与不动产估值」。
- **D9 Electron**：`RATE_HOSTS` 追加 `push2his.eastmoney.com`、`searchapi.eastmoney.com`、`web.ifzq.gtimg.cn`（现有对 rate host 统一补 Referer `fundf10.eastmoney.com` 的写法对这些域名无害，保持统一）。

## 改动清单（均在 `index.html`，除注明外）

1. **`ACCOUNT_TYPES`（L1646-1661）**：`account`→`{name:'基金', emoji:'💹', rateKind:'fund_nav'}`；`stock`→`rateKind:'stock'`。同步注释（L1638-1644）补充 `fund_nav = 基金净值`、`stock = 股票价格`。
2. **`migrateAccounts`（L1079-1121）**：为 `account`/`stock` 补默认字段——`fund_nav` 无 `fundName` 时留空、`stock` 无 `stockMarket` 时留空；`interestRate` 缺失补 0（沿用 `|| 0`）。不强制改名，兼容旧数据。
3. **`Store.refreshInterest`（L1131-1187）**：把逐日「年化计息」抽象为逐日「增长率」`g`：
   - rate 系：`g = annualRate/100/365`（维持现值不变）
   - `fund_nav`/`stock`：`g = dailyChangePct/100`（来自 `QuoteFeed`）
   统一 `principal *= (1+g)`，`accInterest += principal*g`。负增长时同样记账（`accInterest<0` → expense 流水），并把 `if (annualRate<=0) continue;` 改为按 `g` 判断。
4. **`getRateForDate`（L1869-1896）**：新增分支
   - `fund_nav`：有 `fundCode` 且行情可用 → 返回 `null/标记` 走行情；否则返回 `acc.interestRate||0`。
   - `stock`：有 `stockCode` 且行情可用 → 走行情；否则 `acc.interestRate||0`。
   为保持同步签名，新增独立函数 `getDailyGrowth(acc, dateStr)` 返回 `{g, metric}`，`refreshInterest` 改用该函数；`getRateForDate` 保持不变（供其它调用点）。
5. **`getAccountRateInfo`（L1917-1954）**：新增 `fund_nav`/`stock` 分支，返回 `{rate, metric:'daily'|'annual', changePct, source}`：
   - 有行情：`metric:'daily'`，`changePct`=今日涨跌%，`source`=`基金净值（{code}{ · name}·实时）` / `股票收盘价（{code}{ · name}·实时）`
   - 无行情有手动利率：`metric:'annual'`，`source:'自定义年化利率'`
   - 皆无：`rate:0`，`source:'未绑定标的，未跟踪行情'`
6. **账户模态框 HTML（L782-802 附近）**：
   - 复用 `fundCodeGroup`（理财产品名称 + 基金代码 + 匹配）：对 `fund_nav` 显示；标签/提示文案按 kind 动态（`fund`=货币基金 7 日年化，`fund_nav`=按单位净值每日涨跌）。新增 `matchedFundHint` 文案切换。
   - 新增 `stockGroup`：股票名称/代码输入 + 「匹配」按钮 + `stockMatchResults` 容器 + 隐藏的 `stockMarket`。
   - `manualRateGroup` 对 `fund_nav`/`stock` 也显示（标签=「自定义年化利率（%）— 未绑定标的时生效」）。
7. **`updateAccTypeFields`（L2259-2311）**：`fund_nav` 显示 `fundCodeGroup`；`stock` 显示 `stockGroup`；两者都显示 `manualRateGroup`；余额标签用「当前市值」；`ratePreviewGroup` 对 `metric:'daily'` 也显示（改由 `updateRatePreview` 控制文案）。
8. **`updateRatePreview`（L2313-2342）**：`metric:'daily'` 时展示「今日涨跌 ±x.xx%（市值 ¥…）」，来源=`信息源`。
9. **匹配逻辑（L2344-2407 附近）**：新增 `searchStockByKeyword`（东财 suggest）、`searchStockProduct`、`onStockCodeInput`、`setMatchedStock`、`renderStockCandidates`、`pickStockCandidate`；基金侧沿用 `searchMoneyProduct`/`setMatchedFund`，仅按 kind 切文案。
10. **`saveAccount`（L2409-2474）**：新增分支
    - `fund_nav`：`fundCode`、`fundName`（沿用 `accountFundCode`/`pendingFund`）、`interestRate`（选填）。
    - `stock`：`stockCode`、`stockMarket`（`1`沪/`0`深）、`stockName`、`interestRate`（选填）。
    去掉对 `fund_nav`/`stock` 的「必须填代码」硬校验（允许仅手动利率）。
11. **`renderAccounts`（L2753-2810）**：
    - `typeDetail`：`fund_nav`→`基金 · {fundName}`；`stock`→`股票 · {stockName}`。
    - `rateInfo.metric==='daily'` → `📈 今日 ±x.xx%`；`dailyHtml` 改为「日盈亏约 ¥…」（可正可负，正=income 色、负=expense 色）。负盈亏也要展示（现有仅正数展示，需放宽）。
12. **新增 `QuoteFeed` 模块**（放在 `RateFeed` 之后，约 L3680 后）：`SOURCES:{nav:[...],stock:[...]}`、`fetch(kind,code)`、`_buildReturns`（`{日期→涨跌小数}` map）、`changeOn(kind,code,dateStr)`、`preload(accounts)`、`reset()`。
13. **`bootstrapAfterUnlock`（L1123-1130）**：`RateFeed.preloadForAccounts` 之后加 `await QuoteFeed.preload(this.data.accounts)`。
14. **`checkMonthlyReconcile`（L3747）**：文案改为「…并更新保险（手动利率）与不动产估值」。
15. **`electron-app/main.js`（L6）**：`RATE_HOSTS` 追加三个域名。
16. **同步三份 `index.html`**：根目录、`mobile-app/www/`、`electron-app/`（发版脚本已含此步；本地手工同步时三份 MD5 必须一致）。

## 验证

1. `node --check`：从 `index.html` 提取内联 `<script>` 写入临时文件后校验语法。
2. 纯函数单测（node）：用真实抓取的 `lsjz` JSON 与东财 kline JSON 样本，断言 `_buildReturns` 生成 `{date→涨跌}` 正确（如 110022：2026-10-12 DWJZ 2.8070 → 2026-10-13 2.7640，涨跌 ≈ -1.532%）。
3. 三份 `index.html` MD5 一致。
4. 手工/浏览器验证（Electron 或本机 `index.html`）：
   - 新增「基金」账户：输入「易方达消费行业」→ 匹配到 110022 → 保存 → 账户卡片出现「今日涨跌 / 日盈亏约」，账户余额随之变化、生成一条 `invest` 流水。
   - 新增「股票」账户：输入「贵州茅台」→ 匹配到 600519 → 保存 → 卡片显示涨跌与盈亏。
   - 旧「账户」账户（仅手动利率）：启用后仍按年化计息，不报错。
   - 周末/停牌日不产生盈亏。
5. 如用户要求发版，再走 `scripts/release.ps1`（本方案不含发版动作）。

## 不做的事

- 不新增「持仓份额/成本价」字段（以「市值×涨跌幅」等价计算盈亏，无需份额）。
- 不给基金/股票新增数据源设置弹窗（内部固定「主力+备选」，静默切换）。
- 不动 `RateFeed` 现有 catalog/配置/余额宝链路。
